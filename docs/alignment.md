# 浏览器里的自动对齐

## 流程

1. **解码**：用 Web Audio（`OfflineAudioContext`）把音频解码并重采样成 16 kHz 单声道。
2. **特征**：80 维对数梅尔滤波器组，与 Kaldi / kaldi-native-fbank 的默认设置一致（25 ms 窗、10 ms 帧移、povey 窗、预加重 0.97）。
   `tests/fbank.test.js` 用 kaldi-native-fbank 的输出做对照，误差小于 0.01。
3. **声学模型**：NVIDIA NeMo `stt_en_conformer_ctc_small`（CC BY 4.0），由 sherpa-onnx 项目导出并量化为 int8 ONNX（约 46 MB）。
   录音按 30 秒一窗、两侧各留 4 秒上下文送进模型，只保留每窗中间的输出，得到每 40 毫秒一帧的 1025 个 BPE 词片的对数概率。
4. **原文处理**：句子拆成词，每个词按模型的 SentencePiece 词表切成词片。词表文件里没有分数，但 unigram 词表按分数排序，
   所以用“排名的对数”近似分数；这样切出来的结果和模型自己识别时的切法在 99.8% 的词上一致。
   数字、金额、全大写缩写这类读法无法预知的词作为“通配词”，可以匹配任何语音。
5. **强制对齐**：把整篇原文排成一条状态链（句间空隙、词片、词片之间的空白、词与词之间的软空隙），在整段录音上做一次 Viterbi。
   句间空隙可以吸收原文里没有的语音（考试说明、例题、“Now turn to Part 2”）；开头和结尾的空隙代价更低，
   所以像 Part 1 例题那样“先放一遍、再从头放”的情况会对到第二遍（正式播放）上。回溯指针按 2 bit 打包，
   10 分钟录音约需十几 MB 内存。
6. **边界修正**：模型给出的是词片的“尖峰”时刻。再用短时能量把句子起点往前挪到真正开口处（最多 0.4 秒）、
   终点往后挪到声音结束处（最多 0.6 秒），各加一点余量，并保证相邻句不重叠。
7. **置信度**：每个词片在其对齐区间内的最大后验概率取平均。低于 0.6、句中有超过 1 秒原文里没有的语音、
   或整句只有通配词的句子会在校对页标为“待检查”。

## 准确度

在 8 段商业出版的考试听力录音（英式、澳式、北美口音的对话和讲座，共 427 句）上，与逐句人工复核过的时间轴比较：

| 指标 | 结果 |
|---|---|
| 句子起点误差中位数 | 0.12 秒 |
| 句子起点误差 90 分位 | 0.38 秒 |
| 整句错位（对到了别的位置） | 0 |
| 浏览器内耗时（5 分钟录音，单线程 WebAssembly） | 约 30–35 秒 |

剩下超过 1 秒的差异，逐一检查后都是人工时间轴把句前的停顿算进了句子，或者人工时间轴本身标错，自动对齐的位置是对的。
这些测试录音受版权保护，不随项目发布；`tests/align.test.js` 用项目自带的合成示例录音做同样的检查。

## 已知限制

- 原文和录音差别很大（漏了整段、顺序不同）时，对齐会出错；请先保证原文完整。
- 背景音乐很响、多人同时说话的地方，边界可能偏差较大，请在校对页试听。
- 单段录音建议不超过 15 分钟（上限 40 分钟）；更长的请先剪开。
- 手机上对齐较慢、耗电较多；可以在电脑上对齐后导出内容包，再在手机上导入。
